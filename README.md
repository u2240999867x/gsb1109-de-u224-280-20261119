# parquet-tools

![Run Unittest](https://github.com/ktrueda/parquet-tools/workflows/Run%20Unittest/badge.svg)
![Run CLI test](https://github.com/ktrueda/parquet-tools/workflows/Run%20CLI%20test/badge.svg)

This is a pip installable [parquet-tools](https://github.com/apache/parquet-mr).
In other words, parquet-tools is a CLI tools of [Apache Arrow](https://github.com/apache/arrow).
You can show parquet file content/schema on local disk or on Amazon S3.
It is incompatible with original parquet-tools.

## Features

- Read Parquet data (local file or file on S3)
- Read Parquet metadata/schema (local file or file on S3)

## Installation

```bash
$ pip install parquet-tools
```

## Usage

```bash
$ parquet-tools --help
usage: parquet-tools [-h] {show,csv,inspect} ...

parquet CLI tools

positional arguments:
  {show,csv,inspect}
    show              Show human readble format. see `show -h`
    csv               Cat csv style. see `csv -h`
    inspect           Inspect parquet file. see `inspect -h`

optional arguments:
  -h, --help          show this help message and exit
```

## Usage Examples

#### Show local parquet file

```bash
$ parquet-tools show test.parquet
+-------+-------+---------+
|   one | two   | three   |
|-------+-------+---------|
|  -1   | foo   | True    |
| nan   | bar   | False   |
|   2.5 | baz   | True    |
+-------+-------+---------+
```

#### Show parquet file on S3

```bash
$ parquet-tools show s3://bucket-name/prefix/*
+-------+-------+---------+
|   one | two   | three   |
|-------+-------+---------|
|  -1   | foo   | True    |
| nan   | bar   | False   |
|   2.5 | baz   | True    |
+-------+-------+---------+
```

#### Cat CSV parquet and transform [csvq](https://github.com/mithrandie/csvq)

```bash
$ parquet-tools csv s3://bucket-name/test.parquet |csvq "select one, three where three"
+-------+-------+
|  one  | three |
+-------+-------+
| -1.0  | True  |
| 2.5   | True  |
+-------+-------+
```

#### Resumable wildcard listings for archives

`parquet-tools manifest` fetches a `ListObjectsV2` listing page by page and
keeps a checkpoint. It distinguishes a prefix that reached a terminal page
from one that only has verified pages, and it stops explicitly on a wrong
endpoint or a repeated continuation token.

```bash
# First attempt: saves what was confirmed if a later page fails.
$ parquet-tools manifest s3://bucket-name/prefix/* \
    --save-checkpoint listing.json

# Later: continue at the failed page, replaying an old page is safe.
$ parquet-tools manifest s3://bucket-name/prefix/* \
    --checkpoint listing.json --save-checkpoint listing.json
```

Exit status is `0` for a complete conflict-free listing, `2` when only the
confirmed pages are available, `3` when the same key was observed with
different content metadata, and `4` when the credential was used against a
different endpoint/bucket/prefix or pagination could not advance. In the
conflict case both observations are retained and no version is selected by
arrival order.

A completed listing means the service returned a terminal page for this
pagination run. It is not, unless the service says so separately, a
point-in-time snapshot of the bucket. The existing `show`/`csv` wildcard
usage still resolves a list in one call and refuses an incomplete or
conflicting listing instead of silently using it.
